# Keep the last 50 Ended sessions on device, slimmed

When a Session ends with at least one Ended match, we now keep it as an Ended session in localStorage, next to the Clubs and the Active session (ADR-0001). The summary and details screens are calculated from it, so we no longer save a separate summary. localStorage holds only about 5 MB per site in every major browser. A full Session takes roughly 40–100 KB, mostly because of UUIDs and each Match's list of players who were free when it started. So we store a slimmed copy: name, start/end, Point system, Session players (name and Skill), and Ended matches (court, Teams, Target, start/end, Score). Data used only during play is left out: free-at-start lists, Lineups, Queues, Courts, Streak resets and Sitting out. That makes an Ended session about 25–45 KB.

We keep only the 50 most recently ended, and older ones are dropped without asking. If a save still fails because storage is full, we drop the oldest Ended session and try again. We chose this over keeping every Ended session forever, because unlimited history would eventually fill storage and break saving of the Active session. A manual delete was later added next to the cap (see Consequences); it doesn't replace it, since nobody can be relied on to clean up by hand.

## Consequences

- An Ended session can't be resumed or replayed through the queueing engine, because the data needed for Streaks and fairness isn't kept.
- Summaries saved before this change are discarded on upgrade, because they have no matches or session id.
- Shared clubs (ADR-0006): the same slimmed Ended session is published to the Club, `clubs/{clubId}/endedSessions/{sessionId}`, in the batch that ends the Session. Only the Session host creates it, and only in that batch (the Active session is gone after it and the record is named by the Session id kept on the Active session); the creator of a new Shared club may also import its history for an hour. `endedAt` can't be in the future (beyond clock skew), and nobody can change a record; any Organizer can delete them, and deleting a Club deletes its Ended sessions first, so a Club id that is created again has no history. Security Rules can't count, so "the 50 most recent per Club" is what the app lists (newest 50 by `endedAt`, and 50 per Club cached on each device); older ones stay on the server unlisted. Everyone on the Club sees them next to the device's own Ended sessions, each Session once. The device still keeps its own copy of a Session it hosted.
- Deleting an Ended session (added later): one with no Club or of a Local club is deleted on the device by whoever holds it, offline too. One of a Shared club is deleted for everyone, by an Organizer (their Role now, not whether they hosted it), online only: the server record, every device's cached copy, and the hosting device's own copy all go. So a device's cache no longer keeps whatever it already has: it drops an Ended session once the server no longer has it.
